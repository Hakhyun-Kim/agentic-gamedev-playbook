# Agentic GameDev — 실행 절차

당신은 이 스킬이 로드되면 "AI가 만들고 AI가 검증하는" 게임 개발 방법론을 따른다.
핵심 사상: **복잡성을 에셋이 아니라 코드에 둔다.** 그래픽은 절차 생성, 사운드는 Web Audio 합성,
로직은 순수 함수 — 그래야 당신(AI)이 전 과정을 읽고, 고치고, 스스로 플레이해 검증할 수 있다.

## 0. 채택 기준 — 3-Gate

새 게임/기능은 세 관문을 모두 통과할 때만 채택한다:
① **절차성** — 외부 에셋 없이 코드(시드 RNG·수학·캔버스·Web Audio)로 만들 수 있는가?
② **재미** — 코어 루프에 *결정*을 더하는가, 장식인가?
③ **검증가능** — 순수 로직이라 봇이 자동 측정할 수 있는가?

→ 전문: [`references/01-3-gate.md`](references/01-3-gate.md)

## 1. 아키텍처 4대 규약 (첫 커밋부터)

```
data     — 모든 밸런스 수치 한 파일 (튜닝은 여기서만)
engine   — 순수 로직: tick(state, dt) → events[]  (DOM/렌더러 몰라야 함 — 봇과 공유)
render   — state를 그리고 events를 이펙트로
sfx/music — events를 소리로 (Web Audio 합성, 파일 0개)
main     — 배선 컨트롤러 (고정 타임스텝: while (acc >= 1/60) tick(1/60))
```

- RNG는 주입식: 게임=`Math.random`, 봇=`mulberry32(seed)` → 같은 시드 = 같은 전개.
- `tick()`이 이벤트 배열을 반환하게 하라. 봇은 무시하고, 게임은 파티클/사운드로 소비한다.
- 시드 결정론은 봇 검증뿐 아니라 **플레이어 신뢰**에도 쓸 수 있다(온체인/확률형 게임): "확률표
  공개"보다 "결과를 시드로 재현해 보여주기"가 강하다. 실시간 값(`block.timestamp` 등)이 섞이는
  요소는 재현 불가 — 검증 범위를 문서에 명시할 것(2.2.1).
- 같은 수치가 두 언어·두 런타임에 살면 합칠 수 없다 — **소스를 파싱해 대조하는 검사**로 묶어라.

→ 전문(생성기 교체 함정 5가지, 소스 대조 검사): [`references/02-architecture.md`](references/02-architecture.md)

## 2. 코어 루프가 돌면 즉시 밸런스 봇 ★ 이 방법론의 심장

렌더링 없이 engine만 돌리는 `scripts/balance-bot.mjs`를 만든다:
1. **가상 플레이어 프로필** 3종(초보/보통/고수) — 성공률·실수율(sloppy)·행동 빈도를 파라미터로.
   완벽한 플레이가 아니라 *불완전한 사람*을 흉내 내는 게 핵심.
2. 프로필×난이도별 N판(120+) 실행 → **사망 지점 분포**(평균/중앙값/사분위) 리포트.
3. 목표: 실력 순 **단조 증가** + **무한 생존 0%**. 곡선을 data에서 튜닝해 맞춘다.
4. 확정 분포를 `baseline.json`에 저장, `check` 모드로 회귀 검증(중앙값 ±3 이탈 시 exit 1).
5. **사망률만 보지 마라** — 사망 0%는 "안전"이 아니라 "매번 아슬아슬했다"일 수 있다.
   살아남은 판의 체력/자원 손실 폭도 같이 리포트하라.

난이도 곡선 원칙:
- **threat ramp**: 적 HP를 무한정 불리지 말고, 임계 이후 "받는 피해"만 가속 (초반 보존).
- **soft cap**: 곱연산 성장 대신 `value += (CAP - value) * 0.15` 점근.
- threat ramp는 플레이어 성장이 유한할 때만 통한다 — DPS 직결 스탯에도 소프트 캡을 씌워라.

봇 프로필은 둘로 나눠라: `hard`(기준선 전용 — 뜬 뒤 **행동 동결**) / `human`(참고용 —
사람이 못 보는 정보를 주지 않는다). 소극적 행동(후퇴 등)에는 반드시 시한을 둬라.
전투·밸런스를 잴 때 **봇을 순간이동시키지 마라** — 실제 플레이에 없는 상황이라 결과가 왜곡된다.

CI 실측 함정 셋: **프레시 프로필**(CI는 항상 첫 방문자 — 인트로 분기를 범용 클릭 규칙보다 먼저) ·
**줄일 건 로직이 아니라 픽셀**(뷰포트 축소 + 저품질 강제) · **에러 필터**(by-design 404 제외).

→ 전문(표본 없는 결정점 기대값 검사, 시계 주입, 근접사 측정): [`references/03-balancing.md`](references/03-balancing.md)

## 3. 그래픽 — 에셋 0개 "인디 탈출" (적용 순서)

블롭 그림자(가성비 1위) → 파티클 풀(고정 배열) → 떠오르는 데미지 숫자 →
카메라 셰이크(누적→감쇠→**제곱** 적용) → 히트 플래시 → 블룸(밝은 것만) → 안개/비네트.
캐릭터가 필요하면 프리미티브 치비 인간(박스+구, 직업 소품, 등급 망토)으로 절차 생성.
3D라면 여기에 **실시간 그림자 + ACES 톤매핑 + 절차 텍스처**를 얹어야 장난감 느낌이 빠진다.
부팅 후 실측 FPS<45면 스스로 라이트 모드로 강등(+localStorage 캐시).

⚠️ **안 보이는 것을 만들지 마라** — 배경 요소는 만들기 전에 카메라 절두체(NDC 투영)로 30초 검사.
⚠️ **자동 발사가 있다면 카메라 셰이크 대신 위치를 가진 임팩트를 써라** — 명중마다 흔들리면
누적돼 멀미를 유발한다(4.4).

→ 전문(조명 설정값, 그림자 픽셀 차분 검증법): [`references/04-graphics.md`](references/04-graphics.md)

## 4. 사운드 — 파일 0개

`tone(freq, start, dur, type, vol, glideTo)` + `noise(start, dur, vol, freq, q)` 두 도구로 전부 합성.
- 성공=상승 아르페지오 / 실패=부드러운 하강 / 히트=짧은 노이즈+레이트리밋(45~70ms)
- 잭팟(전설/보스)=팡파레·포효 / 저체력=심장박동+붉은 맥동
- BGM이 "삑삑"에서 벗어나려면 여섯 요소가 필요하다: **코드 진행 · 패드(디튠) · 아르페지오 ·
  베이스 · 드럼 · 피드백 딜레이 리버브**.
- 마스터 체인 3단계: **리미터 · 고역 셸빙 · 스테레오 패닝**(+ 재생마다 피치 ±70센트 흔들기).
- AudioContext는 첫 제스처에서 lazy 생성+resume, 뮤트는 localStorage.
- **음소거는 필수 기능** ★: 효과음/배경음을 **따로** 끄게 하고(가장 흔한 요구가 "BGM만 꺼줘"),
  버튼은 HUD에 **아이콘+글자**로, 꺼진 상태는 아이콘 교체+회색/취소선, 단축키(M).
  노드를 끊지 말고 재생 시점에 `if (muted) return`으로 검사.
  소리로만 주는 정보는 반드시 시각 신호와 짝지어라(음소거 사용자 접근성).
- **지속음(sustain) 효과음은 종료 경로 셋 전부에서 회수하라**: 차지 샷처럼 "누르는 동안 유지되는"
  소리는 단발 SFX와 다르다. 정상 해제·오버레이 일시정지·컴포넌트 언마운트 중 하나라도 stop()을
  안 부르면 화면 뒤에서 영원히 운다.

→ 전문(BGM 6요소 구현, 마스터링 수치): [`references/05-audio.md`](references/05-audio.md)

## 5. 진행 설계 — "잭팟"을 반드시 넣어라

스탯만 키우는 강화는 지루하다. **행동이 바뀌는 순간**(관통·연쇄·폭발·광역 감속 같은
진화/특수능력)을 최소 1종 넣고, 눈에 보이게 예고하라. 그 외: 등급 가중치(1/0.5/0.22),
킬 콤보 배율, 죽어도 남는 메타 재화(영구 강화).

- **부가 활동(학습·미니게임)은 옆에 두지 말고 진행의 관문으로** — 사이드 버튼은 아무도 안 누른다.
- **성장 시스템은 하나로** — 레벨과 합성을 둘 다 두면 하나는 반드시 "번거로운 잡일"이 된다.
  판단 기준: 그것이 **선택을 만드는가, 작업을 만드는가?**
- **조합 규칙에 예외를 만들지 마라** — "등급업은 최상위 직전까지만"(예외)보다
  "등급 천장은 직업 세대가 정한다"(규칙)가 이해된다.
- **한 축(사거리 등 커버리지)이 지배하면 그 축을 깎지 말고**, 불리한 쪽에 종류가 다른
  결정력을 줘라(치명타=폭발적 단일 화력, 군중 제어=정지). CC는 반드시 상한과 함께 —
  보스 저항(×0.35) + 재적용 면역(2~3초).

⚠️ 능력을 추가하면 기존 스탯에서 그만큼 빼고 봇으로 재측정할 것.

→ 전문(합성 후반 막다른 길 3종과 처방): [`references/06-progression.md`](references/06-progression.md)

## 6. 게임필 마감 + 조작

잔상 체력바 · 히트 플래시 · 콤보 팝(스프링 이징) · 피격 비네트 · 저체력 맥동+심장박동 ·
데미지/골드 숫자 · 장르 표준 UI(사거리 원, 웨이브 미리보기, 보스 체력바) ·
첫 실행 코치 칩 · 기록 카드 PNG.

- **피드백은 개별 호출부가 아니라 공용 관문 한 곳에** 매달아라(단, 자동 동작은 `silent`).
- ⚠️ **매 프레임 다시 그리는 HUD의 함정** — 갱신 함수 안에서 애니메이션 클래스를
  remove→add 하면 초당 60번 재시작해 글자가 떨린다. **HUD는 값 비교로 가드하고,
  애니메이션은 전이에만 붙인다.**

**조작은 키보드 우선 + UI는 예측형**:
Enter=확인/진행 · Space=주 행동 · Esc=어디서든 한 번에 닫기 · Tab/화살표=대상·위치 순환 ·
숫자키=메뉴 · 이니셜 단축키. 단축키는 버튼 라벨에 표기 + 하단 키 안내 바.
예측형 3규칙: ①다음 행동이 하나뿐이면 자동 진행/자동 닫기(취소 토큰) ②반복 루프는 Enter
원버튼 ③불가능한 행동은 회색 버튼 대신 이유 표시. **"되돌리기 강요" 제거**: "A를 하려면 먼저
B를 취소해야 한다"가 보이면 A를 직접 지원하라.
디테일: 모달 autofocus · 입력 Enter는 stopPropagation · 버튼 클릭 후 blur() · 한글 IME 매핑(ㄴ→S).
⚠️ 편의성은 곧 파워 상승이다 — 패치 후 봇으로 재측정하고 비용을 조일 것(11→22웨이브 사례).

→ 전문: [`references/07-juice.md`](references/07-juice.md)

## 7. 자동 검증 하네스 (당신이 게임을 직접 플레이하기 위한 장치)

- `window.__game = { state, jump(), gold(), ... }` 디버그 훅 (프로덕션은 ?debug 게이트)
- `?rafshim` — 숨김 탭에서 스로틀되는 rAF를 타이머로 대체 (자동화 환경 필수)
- 고정 타임스텝. ⚠️ **히트스톱처럼 시간을 건드리는 연출은 봇 검증 중에 꺼라** — 결정론이 깨진다.
- WebGL 검증 시 `preserveDrawingBuffer` + readPixels로 실제 픽셀 확인
- **연출 전용 훅**(`__game.bossHit(123)`) — 상태를 안 건드리고 이펙트만 재생시켜 스모크로 검사
- 배포 전: 콘솔 에러 0건 + 봇 분포 기준선 통과를 게이트로
- 게이트가 툴체인 크래시로 죽으면 게임을 의심하기 전에 **대조군 셋**을 세우고,
  못 고치는 건 **잘게 쪼개 재시도**하라. **크래시와 실패(기준선 이탈)를 구분할 것.**
- **NPC/이동 로직도 순수 함수로 떼어 실제 배치 위에서 걸려보라** — 막힌 틱에도 좌표를
  매번 넘겨야 한다, 안 그러면 밀린 거리가 다음 틱에 몰아서 반영돼 순간이동처럼 보인다(9.6).

→ 전문: [`references/09-harness.md`](references/09-harness.md)

## 8. 첫 5분 — 심사자·신규 유저는 오래 봐주지 않는다

게임잼 심사는 작품당 몇 분이다. 코어 루프에 닿기까지의 거리가 평가를 지배한다:
- 타이틀에 **"⚡ 바로 시작"**(인트로·허브 건너뛰고 즉시 코어 루프) — 스토리는 남기되 강제하지 마라.
- **1회성 코치 칩**(localStorage) — 튜토리얼 없이 이해되는 조작.
- **목표를 첫 화면에 노출** — 잭팟 시스템이 있으면 "조합까지 N장" 힌트를 보상 카드에 붙여라.
- **자동 시연**(자막 포함, 클릭 한 번) — 직접 플레이할 시간이 없는 심사자용 보험.
- 이 넷은 CI 스모크로 고정하라.

→ 전문: [`references/10-first-5-minutes.md`](references/10-first-5-minutes.md)

## 9. 상시 자동화 — 코어 루프가 재미있어진 다음에 건다

봇을 스케줄에 걸면 개발 루프가 자율적이 된다. 다섯 루프:
1. **배포 게이트 스모크**(푸시마다) — 첫 방문자 동선 + 콘솔 에러 0, 실패면 배포 중단.
2. **야간 밸런스 회귀**(매일) — 분포가 기준선을 이탈하면 이슈 자동 생성.
3. **일일 봇 실주행**(매일) ★ — 그날 시드를 봇이 실제로 플레이하고 **기록을 게임 콘텐츠로 커밋**
   (정적 JSON + 없으면 폴백 = 백엔드 0개로 매일 갱신되는 경쟁 상대).
4. **아침 트렌드 스카우트**(매일) — 조사 → 3-Gate로 거른 추천 top 3~5.
5. **문서 데이터 자동 생성** — git log → 개발 일지 수치·차트 재작성.

크론 5원칙: **멱등** · **시간대 두 번 확인**(크론은 UTC, 게임의 '오늘'은 로컬) ·
**자동 커밋은 다른 워크플로를 안 깨움**(커밋+배포를 한 워크플로에) ·
**실패 시 침묵**(빈 데이터가 틀린 데이터보다 낫다) ·
**드리프트는 실패가 아니라 알림**(종료 코드 분리).

→ 전문(스카우트 프롬프트 설계 6항목): [`references/11-automation.md`](references/11-automation.md)

## 10. 협업 원칙

사용자는 *재미의 방향*을 말한다 — 설계·구현·밸런스·검증·배포는 당신이 자율 수행한다.
버그 리포트는 증상 그대로 받아 원인을 스스로 진단한다. 반복되는 규칙·세계관은
프로젝트의 CLAUDE.md에 승격해 세션이 바뀌어도 유지한다.
실측 근거는 스크린샷 대신 **터미널 SVG**로 남겨라(diff 가능, 1000배 작다).

절대 규칙: 이미지·오디오·3D 모델 파일 반입 금지 — 소스 트리에서 바이너리 확장자를 찾는
**열 줄짜리 테스트로 강제**하라. 불가피하면 종류별 정책이 다르다(폰트는 허용·OFL만·폴백 필수,
사운드는 그대로 재생 금지). 완성되면 공개 저장소 + Pages 배포까지 마친다.

**"됐다"고 말하기 전에 실제로 돌려봐라.** 특히 자동화는 만든 자리에서 한 번 수동 실행해
끝까지 통과하는 것을 보고 커밋한다 — 이 스킬의 CI 함정·시간대 규칙은 전부 문서를 쓰다가가
아니라 실제로 돌려보다가 나온 것이다.
