# Agentic GameDev — 실행 절차

당신은 이 스킬이 로드되면 "AI가 만들고 AI가 검증하는" 게임 개발 방법론을 따른다.
핵심 사상: **복잡성을 에셋이 아니라 코드에 둔다.** 그래픽은 절차 생성, 사운드는 Web Audio 합성,
로직은 순수 함수 — 그래야 당신(AI)이 전 과정을 읽고, 고치고, 스스로 플레이해 검증할 수 있다.

같은 저장소의 `PLAYBOOK.md`(장문판)에 모든 세부 레시피가 있다. `gamedev-playbook` MCP 서버가
연결돼 있으면 `playbook_section` 도구로 섹션을 가져올 수 있다. 아래는 실행용 요약이다.

## 0. 채택 기준 — 3-Gate

새 게임/기능은 세 관문을 모두 통과할 때만 채택한다:
① **절차성** — 외부 에셋 없이 코드(시드 RNG·수학·캔버스·Web Audio)로 만들 수 있는가?
② **재미** — 코어 루프에 *결정*을 더하는가, 장식인가?
③ **검증가능** — 순수 로직이라 봇이 자동 측정할 수 있는가?

## 1. 아키텍처 4대 규약 (첫 커밋부터)

```
data     — 모든 밸런스 수치 한 파일 (튜닝은 여기서만)
engine   — 순수 로직: tick(state, dt) → events[]  (DOM/렌더러 몰라야 함 — 봇과 공유)
render   — state를 그리고 events를 이펙트로
sfx/music — events를 소리로 (Web Audio 합성, 파일 0개)
main     — 배선 컨트롤러 (고정 타임스텝: while (acc >= 1/60) tick(1/60))
```

- RNG는 주입식: 게임=`Math.random`, 봇=`mulberry32(seed)` → 같은 시드 = 같은 전개.
- `tick()`이 이벤트 배열을 반환하게 하라. 봇은 무시하고, 게임은 파티클/사운드로 소비한다.

## 2. 코어 루프가 돌면 즉시 밸런스 봇

렌더링 없이 engine만 돌리는 `scripts/balance-bot.mjs`를 만든다:
1. **가상 플레이어 프로필** 3종(초보/보통/고수) — 성공률·실수율(sloppy)·행동 빈도를 파라미터로.
   완벽한 플레이가 아니라 *불완전한 사람*을 흉내 내는 게 핵심.
2. 프로필×난이도별 N판(120+) 실행 → **사망 지점 분포**(평균/중앙값/사분위) 리포트.
3. 목표: 실력 순 **단조 증가** + **무한 생존 0%**. 곡선을 data에서 튜닝해 맞춘다.
4. 확정 분포를 `baseline.json`에 저장, `check` 모드로 회귀 검증(중앙값 ±3 이탈 시 exit 1).
   이후 밸런스에 영향 주는 변경마다 check를 돌려라 — 손으로 못 잡는 회귀를 잡는다.

난이도 곡선 원칙:
- **threat ramp**: 적 HP를 무한정 불리지 말고, 임계 이후 "받는 피해"만 가속 (초반 보존).
- **soft cap**: 곱연산 성장 대신 `value += (CAP - value) * 0.15` 점근.

봇 프로필은 둘로 나눠라:
- `hard` — 기준선 전용. 기준선을 뜬 뒤에는 **행동을 동결**한다(안 그러면 분포 변화가 게임 탓인지
  봇 탓인지 구분 불가).
- `human` — 사람처럼 판단하는 참고용. 원칙은 **"사람이 못 보는 정보를 봇에게 주지 않는다"**
  (HUD 텍스트·카드 힌트 등 화면에 보이는 것만 파싱). 소극적 행동(후퇴 등)에는 반드시 시한을 둬라 —
  무한 후퇴는 기존 교착 복구를 덮어써 봇을 멈추게 한다.

CI에서 봇을 돌릴 때 실측 함정 셋:
- **프레시 프로필** — CI는 항상 첫 방문자(빈 localStorage)다. 인트로·타이틀 분기를 범용 클릭 규칙보다
  **먼저** 처리하지 않으면 봇이 인트로에서 영원히 갇힌다. 봇 테스트는 빈 프로필에서 하라.
- **줄일 건 로직이 아니라 픽셀** — CI는 소프트웨어 렌더러라 렌더가 병목이다. 뷰포트 축소 + 저품질
  모드 강제로 로직을 건드리지 않고 수 배 빨라진다(실측 1판 30분 → 5판 16분).
- **에러 필터** — 파비콘·선택적 리소스의 by-design 404는 게이트에서 제외하라. 항상 빨간 게이트는
  곧 무시당하고, 그 순간 죽은 장치가 된다.

## 3. 그래픽 — 에셋 0개 "인디 탈출" (적용 순서)

블롭 그림자(가성비 1위) → 파티클 풀(고정 배열) → 떠오르는 데미지 숫자 →
카메라 셰이크(누적→감쇠→**제곱** 적용) → 히트 플래시 → 블룸(밝은 것만) → 안개/비네트.
캐릭터가 필요하면 프리미티브 치비 인간(박스+구, 직업 소품, 등급 망토)으로 절차 생성.
부팅 후 실측 FPS<45면 스스로 라이트 모드로 강등(+localStorage 캐시).

## 4. 사운드 — 파일 0개

`tone(freq, start, dur, type, vol, glideTo)` + `noise(start, dur, vol, freq, q)` 두 도구로 전부 합성.
- 성공=상승 아르페지오 / 실패=부드러운 하강 (기죽이지 않기) / 히트=짧은 노이즈+레이트리밋(45~70ms)
- 잭팟(전설/보스)=팡파레·포효 / 저체력=심장박동+붉은 맥동
- BGM: 16분음표 스텝 시퀀서 + 룩어헤드 예약, 상태별 트랙(준비/전투/보스), 진행도로 템포↑
- AudioContext는 첫 제스처에서 lazy 생성+resume, 뮤트는 localStorage.

## 5. 진행 설계 — "잭팟"을 반드시 넣어라

스탯만 키우는 강화는 지루하다. **행동이 바뀌는 순간**(관통·연쇄·폭발·광역 감속 같은
진화/특수능력)을 최소 1종 넣고, 눈에 보이게 예고하라. 그 외: 등급 가중치(1/0.5/0.22),
킬 콤보 배율, 죽어도 남는 메타 재화(영구 강화).

## 6. 자동 검증 하네스 (당신이 게임을 직접 플레이하기 위한 장치)

- `window.__game = { state, jump(), gold(), ... }` 디버그 훅 (프로덕션은 ?debug 게이트)
- `?rafshim` — 숨김 탭에서 스로틀되는 rAF를 타이머로 대체 (자동화 환경 필수)
- WebGL 검증 시 `preserveDrawingBuffer` + readPixels로 실제 픽셀 확인
- 배포 전: 콘솔 에러 0건 + 봇 분포 기준선 통과를 게이트로

## 7. 게임필 마감 체크리스트

잔상 체력바 · 히트 플래시 · 콤보 팝(스프링 이징) · 피격 비네트 · 저체력 맥동+심장박동 ·
데미지/골드 숫자 · 장르 표준 UI(사거리 원, 웨이브 미리보기, 보스 체력바) ·
첫 실행 코치 칩 · 기록 카드 PNG.

## 8. 첫 5분 — 심사자·신규 유저는 오래 봐주지 않는다

게임잼 심사는 작품당 몇 분이다. 코어 루프에 닿기까지의 거리가 평가를 지배한다:
- 타이틀에 **"⚡ 바로 시작"**(인트로·허브 건너뛰고 즉시 코어 루프) — 스토리는 남기되 강제하지 마라.
- **1회성 코치 칩**(localStorage) — 튜토리얼 없이 이해되는 조작.
- **목표를 첫 화면에 노출** — 잭팟 시스템이 있으면 "조합까지 N장" 힌트를 보상 카드에 붙여라.
- **자동 시연**(자막 포함, 클릭 한 번) — 직접 플레이할 시간이 없는 심사자용 보험.
- 이 넷은 CI 스모크로 고정하라(바로 시작 클릭 → N초 안에 코어 루프 HUD → 코치 칩 노출).

## 9. 상시 자동화 — 코어 루프가 재미있어진 다음에 건다

봇을 스케줄에 걸면 개발 루프가 자율적이 된다. 다섯 루프(자세한 건 `playbook_section "상시 자동화"`):
1. **배포 게이트 스모크**(푸시마다) — 첫 방문자 동선 + 콘솔 에러 0, 실패면 배포 중단.
2. **야간 밸런스 회귀**(매일) — 분포가 기준선을 이탈하면 이슈 자동 생성.
3. **일일 봇 실주행**(매일) ★ — 그날 시드를 봇이 실제로 플레이하고 **기록을 게임 콘텐츠로 커밋**
   (정적 JSON + 없으면 폴백 = 백엔드 0개로 매일 갱신되는 경쟁 상대).
4. **아침 트렌드 스카우트**(매일) — 뉴스·신작·게임잼·GitHub 조사 → 3-Gate로 거른 추천 top 3~5.
   프롬프트에 반드시: *저장소의 백로그·완료 노트를 먼저 읽어 중복 추천 금지* / 출처 링크 강제 /
   각 항목에 규모·첫 구현 스케치 / 읽기 전용(코드 수정 금지) / "오늘은 패스" 목록도 요구.
5. **문서 데이터 자동 생성** — git log → 개발 일지 수치·차트 재작성(수기 통계는 반드시 낡는다).

크론 5원칙: **멱등**(오늘 것 있으면 종료) · **시간대 두 번 확인**(크론은 UTC, 게임의 '오늘'은 로컬 —
끝나고 기록된 날짜와 파일명을 대조) · **자동 커밋은 다른 워크플로를 안 깨움**(커밋+배포를 한 워크플로에) ·
**실패 시 침묵**(교착이면 기록하지 말 것 — 빈 데이터가 틀린 데이터보다 낫다) ·
**드리프트는 실패가 아니라 알림**(종료 코드를 분리: 비정상=실패, 기준선 이탈=이슈).

## 10. 협업 원칙

사용자는 *재미의 방향*을 말한다 — 설계·구현·밸런스·검증·배포는 당신이 자율 수행한다.
버그 리포트는 증상 그대로 받아 원인을 스스로 진단한다. 반복되는 규칙·세계관은
프로젝트의 CLAUDE.md에 승격해 세션이 바뀌어도 유지한다. 절대 규칙: 이미지·오디오·3D 모델
파일 반입 금지(불가피하면 라이선스 기록), 완성되면 공개 저장소 + Pages 배포까지 마친다.

**"됐다"고 말하기 전에 실제로 돌려봐라.** 특히 자동화는 만든 자리에서 한 번 수동 실행해
끝까지 통과하는 것을 보고 커밋한다 — 이 스킬의 CI 함정·시간대 규칙은 전부 문서를 쓰다가가
아니라 실제로 돌려보다가 나온 것이다.
