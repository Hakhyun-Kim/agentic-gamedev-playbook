## 9. 자동 검증 하네스 (Automated Harness)

AI가 헤드리스 브라우저 또는 백그라운드 환경에서 게임을 스스로 구동하고 플레이 검증을 수행하기 위한 전용 내장 도구들입니다.

### 9.1 하네스 핵심 구성 요소

1. **디버그 훅 (Debug Hooks):** `window.__game = { state, jump(wave), addGold(n) }` 형태로 상태 조회 및 강제 변경 API를 글로벌 노출 (`?debug` 쿼리 파라미터로 제어).
2. **`?rafshim` (rAF 대체 심):** 브라우저가 백그라운드 탭이나 헤드리스 환경으로 전환될 때 `requestAnimationFrame`이 스로틀되는 현상을 타이머(setInterval)로 우회.
3. **고정 타임스텝 (Fixed Timestep):** `while (acc >= 1/60) { tick(1/60); }` 형태로 루프를 돌려 프레임 드랍 환경에서도 게임 속도 및 시드 결과의 일관성 유지.
4. **시간 기반 연출 비활성화:** 명중 순간 `dt=0`으로 얼리는 히트스톱(Hit-stop)이나 슬로모션 등 결정론을 깨뜨리는 시각 연출은 고정 타임스텝 모드(봇 검증 시)에서 비활성화 처리.
5. **픽셀 검증 및 캡처:** WebGL Canvas의 `preserveDrawingBuffer` 옵션을 켜두고 `toDataURL()` 또는 `readPixels()`로 화면 차분을 추출하여 조명, 대비, 그래픽 효과를 검증.
6. **순수 함수 로직의 단독 CLI 검사:** 지형 생성이나 수치 조합처럼 렌더링이 불필요한 영역은 Node.js 환경에서 브라우저 없이 수백 개의 맵을 1초 만에 자동 검사.

### 9.2 오디오 노드 생성 카운팅 검증

헤드리스 환경에서는 오디오가 실제로 재생되는지 청음할 수 없으므로, `AudioContext` 메소드를 오버라이드하여 렌더링 시 생성되는 오디오 노드(오실레이터, 버퍼, 피드백 딜레이 등)의 수량을 계측하여 가상 검증합니다.

```js
// Playwright 등을 통해 페이지 스크립트 실행 전 오디오 노드 생성수 카운터 주입
window.__audio = { osc: 0, buf: 0, panner: 0 };
// createOscillator 등의 함수 호출 시 카운트 증가
```

### 9.3 콘텐츠 생성기의 역산 검산

수학 퀴즈나 퀘스트처럼 정답이 명확한 콘텐츠를 절차 생성하는 경우, 수만 개의 생성 결과를 기계적으로 평가(`evaluate(p.text) === p.answer`)하여 오답 문제나 0.3333... 처럼 입력 불가능한 정답이 포함되지 않았는지 사전에 자동 정적 검증합니다.

### 9.4 봇 구동 시 무음(Silent) 처리의 강제

하네스 봇을 통한 자동화 실행 시에는 `?mute` 또는 `?rafshim` 플래그 감지 시 무음 상태로 작동하도록 기본값을 잡되, 사용자의 `localStorage` 음소거 저장값을 덮어쓰지 않도록 전용 가드를 둡니다.

### 9.5 봇 데모(자동 시연)의 실게임 코드 공유

자동 시연 기능(Demo mode)을 별도의 스크립트 각본으로 작성하지 말고, 밸런스 봇의 플레이 판단 모듈(`src/bot.js`)을 그대로 공유하도록 설계합니다. 이렇게 하면 데모 자체가 항상 살아있는 E2E 회귀 테스트 역할을 수행하게 됩니다.
