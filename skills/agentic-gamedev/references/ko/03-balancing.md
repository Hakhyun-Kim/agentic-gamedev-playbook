## 3. AI 자동 밸런싱 ★ (방법론의 핵심)

사람이 일일이 100판씩 기획 수치를 확인하는 대신, **밸런스 봇이 실제 게임 엔진으로 수백 판을 초고속 시뮬레이션하고 사망 분포 리포트를 반환**하게 합니다.

### 3.1 가상 플레이어 프로필

실력대별 플레이어의 행동 특성을 파라미터로 정의합니다.

```js
const PROFILES = {
  '초보': { acc: 0.45, actionsPerTurn: 1, comboChance: 0.15, sloppy: 0.5 },
  '보통': { acc: 0.70, actionsPerTurn: 3, comboChance: 0.70, sloppy: 0.3 },
  '고수': { acc: 0.90, actionsPerTurn: 6, comboChance: 1.0,  sloppy: 0 },
};
```

`acc`(정답/성공률), `sloppy`(실수율) 같은 파라미터로 **불완전한 사람 플레이어의 특성**을 흉내 내는 것이 핵심입니다. 최적의 정답만 내는 완전무결한 플레이만 시뮬레이션하면 실제 사용자가 느낄 난이도를 도출할 수 없습니다.

### 3.2 사망 분포 리포트

N판의 테스트를 돌려 도달 웨이브/층의 분포(평균, 중앙값, 사분위수)를 확인합니다.

```
[보통] 초보  평균 9.1웨이브 (중앙값 9)    ← 목표: 초보자도 초기 웨이브는 통과하고 적절한 벽을 만남
[보통] 보통  평균 17.8웨이브 (중앙값 18)  ← 목표: 중반 웨이브까지 무난히 몰입
[보통] 고수  평균 24.3웨이브 (중앙값 25)  ← 목표: 숙련자는 확실히 더 깊이 진입
```

실력 수준에 맞춰 도달 수치가 단조 증가하는지, 무한 생존(밸런스 붕괴) 현상이 없는지 확인합니다.

### 3.3 기준선 (Baseline) 및 회귀 검증

조율된 난이도 분포를 `baseline.json`에 기록해 두고, 코드 변경 커밋마다 봇을 재실행하여 **중앙값이 허용 오차범위(예: ±3웨이브)를 벗어나면 빌드를 실패** 처리합니다.

```bash
node scripts/balance-bot.mjs 120 check   # 기준선 이탈 시 exit code 1
```

> **용사 수학 디펜스 사례:**
> 전설 특수 능력을 추가했을 때 이 검증이 "고수 난이도 중앙값 22→29 급등"을 즉시 감지해냈습니다. 스노우볼 억제 로직을 추가해 바로 난이도를 보정했죠. 사람의 수동 테스트로는 잡기 힘든 밸런스 회귀였습니다.

*버그 수정으로 인한 분포 변동 주의:*
게임 내부 로직 버그를 고치면서 봇의 중앙값이 상승한 경우, 이는 되돌려야 할 회귀가 아니라 정상화 과정입니다. 이 경우 신규 수치로 `baseline.json`을 업데이트하고 사유를 주석으로 명시해 둡니다.

### 3.4 측정용 봇 vs 사람형 봇의 분리

기준선을 측정하는 봇의 AI 판단을 함부로 고치면, 난이도 변화가 게임 때문인지 봇 알고리즘 때문인지 구분할 수 없게 됩니다. 따라서 봇 역할을 분리합니다.

- **`hard` (측정용 봇):** 기준선 판정 전용. 일단 설정되면 **AI 행동 로직을 동결**합니다.
- **`human` (사람형 봇):** 실제 사람처럼 행동하는 봇. 화면에 표시되는 HUD 정보(HP, 조합 힌트, 테두리)만 읽고 판단합니다.

사람형 봇에 "체력이 낮으면 후퇴" 같은 소극적 행동을 추가할 때는 반드시 **시한(Timeout)**을 두어야 교착 상태(Stuck)에 빠지지 않습니다.

### 3.5 난이도 곡선의 2대 원칙

**① Threat Ramp — 적 체력을 부풀리지 말고 "플레이어가 받는 피해량"을 후반에 가속할 것**

```js
// 적 HP를 부풀리면 초반 구간까지 딱딱해지므로, 후반에 받는 피해만 가속함
export const castleDmgScale = (w) => 1 + Math.max(0, w - 15) * 0.08;
```

**② Soft Cap — 곱연산 폭발 대신 상한선에 점근되도록 설계할 것**

```js
value += (CAP - value) * 0.15;   // 초기 선택은 효과가 크지만 후반에는 자연스럽게 완만해짐
```

백층 던전은 이동속도와 사거리에, 용사 수학 디펜스는 웨이브 HP 곡선에 이 소프트 캡을 적용했습니다.

### 3.6 CI 실행 환경의 3대 주의사항

1. **프레시 프로필 준비:** 봇은 언제나 세이브 데이터가 없는 빈 상태(초기 튜토리얼/인트로)로 시작하도록 배선합니다.
2. **해상도 축소로 픽셀 연산 감소:** CI 헤드리스 환경에서는 뷰포트 크기를 640x360으로 낮춰 시뮬레이션 속도를 극대화합니다.
3. **의도된 404 및 외부 에러 제외:** 404 노이즈(파비콘 등)나 외부 서버 에러로 CI 테스트가 막히지 않도록 필터링합니다.

### 3.7 기대값 기반 닫힌 식 검사 (Close-Form Expectation)

선택지가 단순한 "Push-Your-Luck"(한 번 더 도전할지, 정산하고 나갈지) 메커닉은 수백 판을 돌릴 필요 없이, 손익분기점 기대값이 0이 되는 지점을 수학적 공식을 써서 단언 검사(Assertion)로 묶어둘 수 있습니다.

### 3.8 시계 주입 (Clock Injection)

특정 시간대나 요일에 맞춰 발동하는 이벤트는 `isEventNow(now = Date.now())`처럼 시간 인자를 주입받도록 구성합니다. 로컬 테스트 및 CI에서 시간을 임의로 변경하여 밀리초 단위로 이벤트 동작을 검증할 수 있습니다.

### 3.9 근접사(Near-Miss) 지표 측정

사망률 0%가 단순히 위협이 없었다는 의미는 아닐 수 있습니다. 살아남은 라운드에서 잃은 체력의 최대/평균 폭(근접사 폭)을 함께 측정하면, "죽지는 않지만 식은땀 나는 긴장감"이 유효한지 파악할 수 있습니다.

### 3.10 봇 순간이동 검증 금지

전투 검증 시 봇을 보스나 출구 앞으로 직접 순간이동시키는 유도 테스트는 피하세요. 이동 과정에서 겪는 회피/전투 기회가 지워져 실제 플레이와 완전히 다른 결과가 발생합니다.

### 3.11 전투 중 무거운 렌더/상태 갱신 미루기

실시간 전투 중 정예 몬스터 처치 시 대량의 UI 상태 갱신이 일어마면 프레임 드랍이 생기고, 이 순간 프레임 판정에 의해 봇이 억울하게 사망할 수 있습니다. 보상 지급 처리는 전투가 잠시 소강되는 포털 통과 등의 안전 지점으로 미루는 편이 깔끔합니다.
